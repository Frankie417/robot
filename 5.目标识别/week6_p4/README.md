# Ch6 固定 P4 四色垃圾桶自动分拣

物块每次固定放在 **P4**，相机只判断 P4 上的物块颜色，机械臂沿固定抓取路径将其投入对应垃圾桶。四桶投放 XYZ/Pitch 采用本次提供的数据，原始 Roll 保留用于核查。程序、配置和 notebook 都是新文件，原 week3/week4/week5 不修改。

## 1 在哪里运行

整套程序运行在 **Jetson**：使用 Jetson 上观察 P4 的摄像头和原机械臂 SDK。本机只通过 Micro-USB 网络在浏览器打开 `http://192.168.55.1:8888` 操作 JupyterLab。Ch6 不需要运行 week7 手势程序或手势接收服务；先关闭它们，避免抢占机械臂串口。

把整个 `week6_p4` 文件夹上传到 Jetson，保留同目录模块，打开 **`week6_color_sorting.ipynb`**。不需要 PyTorch、MediaPipe 或额外手眼像素转换。本次是固定 P4 抓取，不支持把物块随意放到任意位置。

主要文件：

| 文件 | 用途 |
| --- | --- |
| `week6_color_sorting.ipynb` | 首选入口，包含参数、实时界面和结束单元 |
| `week6_color_sorting.py` | 实时画面、自动分拣、实测记录、控制面板 |
| `bin_map.json` | 四色映射、P4 抓取点、四桶投放及上方点、HSV 和时序 |
| `sorting_core.py` | 四色检测、连续帧确认、防重复抓取、动作计划 |
| `hardware_backend.py` | 离线 IK 预检、SDK 抓放与等待到位 |
| `arm_interrupt.py` | 同线程中断轨迹、当前位置保持、检查新鲜角度反馈 |
| `read_current_pose.py` | 只读取当前示教位姿，正确转换角度和 Z 补偿 |
| `test_week6.py` | 合成图像和模拟动作自检，不连接真机 |
| `prepare_assets.py` | 一次性创建配置与 notebook 的构建脚本，用户无需运行 |

## 2 先预览与演练

1. 在 Jetson JupyterLab 中按顺序运行 notebook 参数和面板单元。默认是 **simulation 演练**，不会连接舵机。
2. 点击“启动摄像头”。沿用 week5 的 `cv2.VideoCapture(0)`，不强制设置宽高、帧率、MJPG 等参数；避免旧代码出现过的设置后取帧失败。
3. 输入 x/y/width/height，点击“应用 P4 ROI”。白框只圈 P4 物块所在区，排除彩色垃圾桶、机械臂和其他色块。初始输入框仅为示例，必须根据真实画面修改。
4. 点击“开始自动分拣”，把一个物块放在 P4。程序同时识别红黄绿蓝，不需要先选择待识别颜色。
5. 单个目标颜色及位置连续稳定 6 帧后，自动执行一次演练计划，进入 BUSY。
6. 演练不拿走实物，你需要手动移走 P4 物块。动作结束后先等待约 0.5 秒，再连续观察到 8 帧空区才会重新准备，然后再放下一块。

画面在 BUSY 期间仍持续更新，但不累计确认帧，也不把机械臂遮挡误计为取物后空区。如果实际抓取失败、物块仍在 P4，程序保持 RESET 等待，不会对同一物块连续重复抓取。多个目标、多个颜色或明显黑屏都不触发；黑屏不算空区。

点击“停止当前动作”可以请求取消剩余轨迹并在当前位置保持。相机取帧失败也会停用新任务并请求中断。停止是软件保护，不替代设备物理急停。真机中断后检查现场，解除停止、回观察位、重新圈 P4 ROI，再开始新任务，不续接旧轨迹。

## 3 当前位姿数据和必须核查的差异

### 桶位是投放位置

| 颜色 | 垃圾桶 | X mm | Y mm | Z mm | Pitch ° | 原始 Roll ° | 仅供诊断的单圈等效 Roll ° |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| green | 厨余垃圾 | 122.8 | 114.8 | 122.8 | 112.7 | -945200.4 | 159.6 |
| yellow | 其他垃圾 | 219.0 | 99.8 | 135.6 | 106.5 | 137329.9 | 169.9 |
| blue | 可回收物 | 207.8 | -141.3 | 133.3 | 104.5 | 137329.9 | 169.9 |
| red | 有害垃圾 | 127.4 | -131.8 | 146.4 | 94.5 | 148789.0 | 109.0 |

等效角度只由数学取模得到，不能证明原始读数可靠，也不能证明姿态实际正确。`bin_map.json` 的运动位姿 `roll_deg` 默认留空，诊断候选另存 `diagnostic_modulo_roll_deg`，不直接发送给真机。

每个桶有独立 `pose` 和 `above`。桶上方点初值为同 X/Y、Z+15 mm，**只是离线可达的参考，并不代表能越过实际桶壁**。必须检查投放高度、夹爪与桶沿间隙、中转路径；必要时分别重新示教。不要无条件改成 Z+55：本地现有 SDK 在候选 Roll 下，绿/黄/蓝三桶的 Z+55 点没有逆解。

### P4 抓取高度不能直接照抄 week4 的放置高度

week3 明确的底层抓取参考是：

```text
Pick  : X=192.2, Y=-11.2, Z=13.8, Pitch=132.7°, Roll=144.5°
Above : X=192.2, Y=-11.2, Z=68.8, Pitch=132.7°, Roll=144.5°
```

week4 第一块放到 P4 的数据是 `(198.2,-11.2,33.0,132.7°,144.5°)`；它是堆叠放置目标，不是相同条件下已证明的抓取高度。新程序采用 week3 抓取参考，但需要确认当前物块尺寸、夹爪和桌面条件是否一致。

观察/中转位初值为 `(150,0,200,96.1°,180°)`，是显式可检查的 Home 参考；不是自动把 SDK 动态 Pitch 隐藏掉。若相机安装在机械臂上，必须回同一个观察位后设置 ROI，不能中途更改相机位置。

## 4 如何重新读取桶位 Roll 和 P4 姿态

先用原来的示教工具把机械臂放到待记录的位置，保持舵机位置。关闭旧程序的串口连接后，在 Jetson 终端运行下面的只读示教脚本：

```bash
python3 read_current_pose.py \
  --sdk-dir '/home/jetson/Notebook/4.机械臂OpenCV视觉处理实验' \
  --arm-port /dev/ttyTHS1 --label green
```

对应标签可用 yellow、blue、red、p4_pick、p4_above、green_above 等。每次新建 `results/taught_时间.json`，不覆盖原配置，也不发 Home、开爪、运动或卸力指令。

脚本使用 SDK 正运动学的原始弧度，只做一次 `degrees()`；同时记录：

- `fk_pose_mm_deg`：当前物理末端的正运动学读数。
- `command_pose_mm_deg`：扣除 SDK 内置 Z 补偿后的可回放命令坐标。配置要用这一项，否则 `set_tool_pose()` 再补偿一次会造成高度偏差。

把确认后的数值填写到本新建 `bin_map.json` 的对应 `pose/above`。若只确认 Roll，其余 XYZ/Pitch 仍采用用户原表，需要同时确认这些值属于该 SDK 的命令坐标约定。

在核查完 P4 抓取点、上方点、四桶投放/上方点、观察点和实际路径后，设置：

```json
"physical_calibration_confirmed": true
```

这是现场标定状态记录，不能用把 false 改 true 的方式绕过未完成的标定。缺 Roll、异常角度、上方点错误或 IK 无解仍会在连接前拒绝运行。

## 5 真机启动顺序

1. 关闭 week3/week4、旧 week6、week7 接收端及其他占用相机/舵机串口的程序。
2. 在 `bin_map.json` 核对 `sdk_dir`、`arm_port` 和 `camera_device`。使用这台机械臂自己的 SDK/config；不复制其他机械臂的标定文件。
3. 完成上述示教和路径核查，重新加载 notebook 的 `config`，创建新面板。旧面板先点击关闭预览，等线程和串口退出。
4. 点击“连接真机”：先逐个检查所有关键目标 IK，再连接舵机；连接不自动运动。
5. 点击“回观察位”。这一步会实际运动，确认路径无障碍。
6. 在当前相机画面中重新应用 P4 ROI，然后点击“开始自动分拣”。
7. P4 一次只放一个物块，先测一种颜色，再扩展到四色随机顺序。每轮等机械臂复位、空区确认后再放新物块。
8. 观察真实抓取和投放结果，再在面板填写真实颜色、实际投放桶和人工判定，点击“记录本轮实测”。

机械臂动作：先开爪 → P4 上方 → 垂直下降抓取 → 合爪 → 垂直抬升 → 高位中转 → 对应桶上方 → 下降投放 → 松爪 → 垂直撤离 → 回观察位。

夹爪沿用原 SDK 软开闭。初值：抓前张开 pi/4 弧度、投放释放 0.40 弧度（参考 week4），闭合 0；移动 1.5 秒，夹爪动作 0.7 秒。实际夹持效果需要实测；没有夹持力/抓取成功传感器，程序 done 不自动等于成功抓住或投进桶。

失败时不强制开爪或回 Home，以免物体掉落、碰撞。先取消后续动作并保持当前位置，再人工检查。

## 6 识别参数和防重复机制

HSV 沿用 week5 的现场逻辑：红色两个 H 区间，绿色 V 下限为 35；最小轮廓面积 700，5×5 开闭运算。相机曝光或背景变化时仍需现场调参。

自动抓取条件是 **P4 ROI 中只有一个有效轮廓、颜色一致、位置相对首次确认中心偏移不超过 18 像素，并持续 6 帧**。颜色下拉框仅用于实测真值填写，不控制识别目标。

```text
READY → DETECT → CONFIRM → BUSY → RESET → READY
                       异常/停止 → 中断并保持 → ERROR/STOPPED
```

RESET 只接受动作结束之后的空区帧，忽略 BUSY 遮挡及结束后 0.5 秒的画面。持续看到同一物块不会自动重复抓取；需要清空 P4 后才可重启。若人工把下一块放得太快、没有留下空区帧，会继续等待 RESET，这是预期行为。

相机线程持续预览；只有单个动作线程连接和操作 SDK。所有运动角度在 JSON 中为度，调用 SDK 时只换算一次弧度。取物位置固定，因此像素中心仅用于判断稳定性，不用于计算机械臂 XYZ。

## 8 结果记录与实验报告

每次面板运行会新建 `results/时间/`：

- `_raw.png` 和 `_detect.png`：触发分拣那一帧的原图、识别图。

没有触发的试验或视觉误识别导致未抓取的情况，也应在报告测试表中记录；不要只用自动执行日志统计成功率。面板本轮记录只对应最近一次已结束的分拣，不是完整的随机试验采集系统。

测试截图应覆盖四种颜色、一次完整抓放、RESET 防重复及失败分析。不要把模拟、自检或数学取模诊断写成真机成功。

依赖沿用 Jetson 课程环境：Python 3.6+、NumPy、OpenCV、pyserial、ipywidgets。直接运行 `.py` 的面板需要 Jupyter 显示环境，建议始终使用本 notebook；终端用于诊断、示教读取和自动测试。
