## 8 当前手势与状态逻辑

| 标签 | 实际手形 | 作用 |
| --- | --- | --- |
| One | 只伸食指 | 选择张开夹爪 |
| Two | 伸食指和中指 | 选择闭合夹爪 |
| Three | 伸食指、中指、无名指，小指弯曲 | 选择回到零点 |
| OK | 拇指食指成环，其余三指伸直 | 确认并执行候选动作 |
| Five | 五指张开 | 中断当前动作、保持位置、锁定后续动作 |

One/Two/Five 来自官方类别 Pointing_Up/Victory/Open_Palm；Three/OK 通过 21 个关键点的几何规则判断。

- 最低分数 0.70。
- One/Two/Five 显示模型分类分数；Three/OK 显示几何余量分数，后者不是概率。
- 选择和 OK 确认各要求连续 3 帧。
- Five 连续 2 帧通过即触发，不需要先准备或做 OK，BUSY 期间也有效。
- 候选超时为 8 秒。
- 每轮必须点击“准备下一条”；动作结束或中断后不会自动再执行。
- 中断后先收手，再解除停止、重新准备。持续举着 Five 会再次触发停止。
- 多手被检出时不允许触发动作。
- 几何阈值：伸直比值 1.85，弯曲比值 1.55，OK 指尖距离/掌宽 0.42。

操作例子：点击准备 → 做 One → 看到候选 One → 做 OK → 张开夹爪。动作过程中做 Five，无需 OK，触发当前动作取消。

## 9 当前通信与软件制停实现

连接结构：

```text
本机摄像头
  → 本机识别和状态机
  → Micro-USB USB 网络 HTTP
  → Jetson 接收服务
  → 原机械臂 SDK / Jetson 内部 UART
  → 机械臂
```

本机到 Jetson 不再使用 COM 桥接。Jetson 到舵机的原有内部 UART 仍保留，这是另一层连接。

网络接收服务默认端口 8765，地址为 `http://192.168.55.1:8765`。每次启动接收端生成新的 TOKEN 和会话编号；本机需要填入当次 TOKEN。网络请求绕过系统代理。

服务包含状态查询、心跳、动作提交、结果查询、停止和解除停止接口。每条动作有独立编号；接收端保留最近 1000 条结果用于去重。停止会更新指令代次，拦截停止前延迟到达的旧动作。服务重启后必须重新连接。

动作提交后，本机轮询最终结果；停止使用独立 HTTP 请求，不等待动作先执行结束。

Five 的接收端处理：

1. 置取消事件并锁定新动作。
2. 在 SDK 下一次轨迹写入或回调时中断循环，停止继续发送轨迹点。
3. 由同一动作线程操作 UART，避免多个线程同时访问 SDK；读取各舵机实际角度，以当前角度覆盖原运动目标。
4. 要求新鲜角度反馈，不能用 SDK 过期缓存证明成功。
5. 连续两次反馈中，各关节变化不超过 0.5°，且距保持目标不超过 1°，才标为反馈稳定。
6. 读取、下发或稳定检查失败时返回失败，保持锁定，禁止软件解除停止。

适配层还将 SDK 原先可能吞掉的串口写异常改为向上报告。没有使用阻尼卸力冒充位置保持。

断连处理：本机约每 0.25 秒发送一次心跳；Jetson 心跳超时阈值约 1.5 秒，随后自行取消动作并保持位置。断网后本机发出的 Five 可能无法送达，看门狗是后备停止路径。

**准确表述：这是可以中断当前动作的软件保护停止，不是经过认证的硬件急停。** 识别、网络、Python 调度、逐个关节通信和机械惯性均有延迟；尚未测定真实机械臂的制停延迟和残余运动距离。

## 11 到实验室的操作顺序

### 11.1 连接与网络演练

1. 实验箱正常供电，用支持数据传输的 Micro-USB 线连接本机和 Jetson 数据口。
2. 本机访问 `http://192.168.55.1:8888`，进入 Jetson JupyterLab。
3. 在 Jetson 新建目录，把 `receiver_usb.py` 和 `arm_interrupt.py` 两个文件一起上传。
4. 关闭其他控制同一机械臂的程序或 notebook，避免争抢内部串口。
5. 在 Jetson 的 Terminal 进入上传目录，运行：

```bash
python3 receiver_usb.py
```

6. 本机通过 `start_usb_gesture.bat` 打开网络版，地址保持 `http://192.168.55.1:8765`，填入接收端打印的 TOKEN，点击连接并查询。
7. 确认接收端模式是 simulation，解除停止、准备，测试 One → OK，再在 2 秒模拟动作内做 Five，确认结果为 interrupted。

### 11.2 真机联调

结束模拟服务后，在 Jetson 运行以下示例；SDK 目录和机械臂内部串口必须按现场实际配置确认：

```bash
python3 receiver_usb.py --hardware \
  --sdk-dir '/home/jetson/Notebook/4.机械臂OpenCV视觉处理实验' \
  --arm-port /dev/ttyTHS1
```

`/dev/ttyTHS1` 来自已有 SDK 默认配置，尚未现场核实。必须使用这台实验机械臂自己的配置和标定数据，不用本机拷贝替代现场配置。

接收端需要原 SDK 的配套文件、NumPy、pyserial；不需要在 Jetson 安装 MediaPipe。适配层检查在线舵机 ID 是否为 0..5。初始化使用 `is_init_pose=False`，不自动回零。

重启接收服务后，本机断开再重新连接，填入新 TOKEN。确认模式为 hardware。

先测试空载夹爪张开，再测试闭合，最后在空间允许时测试回零。应先在缓慢、可控的动作中触发 Five，现场观察所有关节实际停止，再继续实验；有碰撞风险时使用设备物理急停或电源装置。
