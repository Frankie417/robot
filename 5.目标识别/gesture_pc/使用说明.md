# 本机手势识别与串口桥接

本目录是新建的独立实现，原 notebook、PDF、Word 和 README 未修改。本机负责摄像头采集、MediaPipe 手势识别、去抖和指令确认；实验室电脑或 Jetson 运行 `receiver.py`，接收串口指令并调用实验室原有机械臂 SDK。

## 现在开始测试

双击 `start_gesture.bat`。使用工作空间内新建的 `.venv-gesture`，无需激活环境，也不需要连接 Jetson 或机械臂。

1. 点击“启动摄像头”，默认编号 0。如无法打开，关闭其他使用摄像头的程序，或尝试编号 1。
2. 单手面向镜头，手掌和五指完整入镜。依次观察 One、Two、Three、OK、Five 标签；不通过时不会触发动作。两只手被模型检出时拒绝触发。
3. 验证识别效果：在“真实手势”选择实际摆出的手势，稳定后点击“记录识别测试”。建议每种手势至少测 10 次，并加测无手、随意手形、不同距离和光照；不要只记录成功的帧。
4. 验证指令流程：点击“准备下一条”，做 One/Two/Three，看到候选后再做 OK。稳定 3 帧后仅执行一次演练动作，约 0.7 秒后结束。保持 OK 不会重复触发；下一轮需再次点击准备。
5. Five 连续 2 帧，或点击“停止锁定”，拒绝后续动作。解除后仍需重新准备。停止锁定不能打断已经开始的机械臂 SDK 动作。
6. 每轮指令结束可点“记录本轮指令”。备注中写预期动作和现场观察。本机演练、串口接收端演练、硬件模式分别记录，不自动把 SDK 返回判为机械臂动作正确。

截图、CSV 和事件日志保存在 `gesture_pc/results/每次启动的时间/`。`recognition_trials.csv` 是识别测试；`command_trials.csv` 是指令流程记录；`events.jsonl` 是收发过程。自动自检不写入这两份实验 CSV。

## 手势与实现

| 标签 | 实际手形 | 指令作用 | 识别来源 |
| --- | --- | --- | --- |
| One | 只伸食指 | 选择张开夹爪 | 官方 Pointing_Up |
| Two | 伸食指和中指 | 选择闭合夹爪 | 官方 Victory |
| Three | 伸食指、中指、无名指，小指弯曲 | 选择回到零点 | 21 个关键点的几何规则 |
| OK | 拇指与食指成环，其他三指伸直 | 确认候选动作 | 21 个关键点的几何规则 |
| Five | 五指张开 | 停止锁定 | 官方 Open_Palm |

One/Two/Five 显示模型分类分数；Three/OK 显示几何余量分数，不是概率。当前最低分数 0.70；伸直比值阈值 1.85、弯曲比值阈值 1.55、OK 指尖距离/掌宽阈值 0.42，位于 `recognition.py`。先测实际表现，再依据失败样例调整新文件。

状态流程：点击准备 → WAIT → One/Two/Three 连续 3 帧 → SELECT → OK 连续 3 帧 → CONFIRM/EXECUTE → 完成 → WAIT（未准备）。候选 8 秒超时后失效。EXECUTE 期间不接收新的动作；Five 停止仍可进入 STOPPED。通信失败或执行结果未知时锁定，禁止自动重发。

实验 5 模板写有“基于 PyTorch”，本实现沿用原手势 notebook 的 MediaPipe 官方预训练模型，并不是 PyTorch 训练实现。若老师明确要求 PyTorch，需要另行实现，报告应如实注明实际技术路线。实验七的 Fist 是建议手势，本方案沿用已有设计的 Five 停止，实测报告中应保持一致。

## 下午串口联调

结构为：本机摄像头 → 本机识别与状态机 → 串口桥接 → 接收电脑/Jetson → 原 SDK → 舵机串口 → 机械臂。

桥接串口和机械臂控制串口是两个接口。电脑之间需要能形成双向串口链路的转接设备/线缆，具体 COM 或 `/dev/ttyUSB*` 在现场确认。普通 USB 数据线并不一定形成串口。桥接使用 115200、8N1、UTF-8/ASCII JSON，一条消息一行；这里的 JSON 不能直接发送到舵机板。

先把 `receiver.py` 复制到实验室电脑。接收端演练只依赖 Python 和 pyserial，不需要 MediaPipe：

```powershell
python -m pip install pyserial==3.5
python receiver.py --port COM8
```

Jetson 示例：

```bash
python3 receiver.py --port /dev/ttyUSB0
```

本机刷新串口，选择连接实验室电脑的 COM 号，点击“连接并查询”。确认接收端显示 `simulation`，再解除停止、准备，完成一次 One → OK。接收端会先回 `accepted`，执行演练后回 `done`，本机等待 `done` 才解除 BUSY。先验证三类动作、Five 停止和解除，再启用真机。

接收端真机示例（把路径和端口换成现场实际值）：

```bash
python3 receiver.py --port /dev/ttyUSB0 --hardware --sdk-dir '/home/jetson/Notebook/4.机械臂OpenCV视觉处理实验' --arm-port /dev/ttyTHS1
```

Windows 接收端同样可用 `--sdk-dir` 指向实验室 SDK 文件夹，`--arm-port COM6` 指向机械臂。必须使用对应那台机械臂的标定配置；当前电脑的拷贝不能替代现场标定。初始化使用 `is_init_pose=False`，不自动回零。第一项先验证夹爪张开，再验证闭合，最后在空间允许时测试回零。

协议示例：发送 `{"id":"唯一编号","command":"open_gripper"}` 加换行；接收端回相同 id 的 `accepted` 和最终 `done/error`。支持 `status`、`stop`、`clear_stop`、`open_gripper`、`close_gripper`、`home`。最近 1000 个 id 在接收端进程内去重；重启接收端后缓存失效。本机超时不会自动重发。

## 环境与自检

本机固定 Python 3.11、MediaPipe 0.10.21、OpenCV contrib 4.11.0.86、NumPy 1.26.4、pyserial 3.5。OpenCV 使用 contrib 这一套，不要在同一环境再装 opencv-python 或 headless 版本。

从本目录执行：

```powershell
..\.venv-gesture\Scripts\python.exe test_flow.py
..\.venv-gesture\Scripts\python.exe diagnose.py
```

`test_flow.py` 验证确认、超时、低分中断、BUSY、停止、串口协议往返和重复 id 去重。`diagnose.py` 验证模型和真实摄像头取帧；这些结果只证明程序链路可运行，不是实际手势准确率或机械臂动作验收。
